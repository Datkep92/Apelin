# 会话生命周期与存储的三版本重构计划

日期：2026-10-29。基线：Apelin 0.2.6，提交 `308d31574e15eee21b154a3f6fca14a8e2671a39`。

本轮重构分三个产品版本完成：先修复重复打开和终态，再拆开历史浏览与运行路径，最后完善模型上下文恢复。下文以 0.2.7、0.2.8、0.2.9 表示计划发布顺序；实际版本号按发布安排确定。本计划不代表功能已经实现，也不修改当前版本配置。

## 实施边界

- **不引入 SQLite**，也不引入其他数据库、ORM 或通用存储框架。沿用文件、追加日志、原子替换和可重建索引。
- **不修改、不升级、不 fork kwwk，不修改其本地依赖检出内容，不等待上游合入补丁。** 三个版本固定使用 `fb74cf5d855a6dbc60da38187e10d012e30a240a`；不得通过间接依赖解析改变该 revision。依据是 [Package.resolved](../../Apelin.xcodeproj/project.xcworkspace/xcshareddata/swiftpm/Package.resolved)。
- 改动限于 Apelin 的宿主、worker 适配层、协议、App、持久化和相关验证。授权仍由 root 宿主管理，mobile 数据不能成为授权依据。
- 保留模型消息顺序、工具调用 ID、推理签名、不透明供应商字段和现有提示词缓存语义。展示历史不能反推为模型上下文；上下文压缩不能删除展示历史。
- 不承诺进程死亡后精确续跑工具。副作用是否完成无法确定时，保留现场并标记中断，不自动重执行。
- 本周期不做全局附件去重、自动历史清理、历史附件垃圾回收或默认日志分段。若第三版实测仍证明单文件是瓶颈，再评估分段，不把它作为预设迁移要求。

### kwwk 适配能力与限制

固定 revision 提供 `AgentInitialState.messages`、`agent.state.messages` 和 `subscribe`。`messageEnd` 更新状态后通知订阅者；其公开 `SessionRecorder` 也通过消息结束、轮次结束和压缩事件保存上下文。Apelin 可使用现有接口实现自身检查点，不以接入 `SessionRecorder` 为前提；事件顺序、压缩和失败路径仍须契约测试。

`ImageContent.data` 要求 Base64 字符串，没有文件引用或延迟加载接口。第三版只承诺图片在磁盘上外置，并在向 kwwk 提供上下文时还原。图片进入活跃上下文后仍可能常驻为 Base64；不承诺 kwwk 内部惰性加载或请求体流式编码。持久化收益与运行时内存收益分别测量。

若某项能力无法通过固定版本的公开接口可靠完成，应收紧该项实现并记录限制，不能以修改依赖作为隐含后续步骤。

## 已确认的问题

| 问题 | 当前行为及影响 |
| --- | --- |
| 并发打开 | 宿主登记会话前存在异步等待，worker 初始化也可重入；客户端超时不等于后端操作取消，重试可能叠加打开。 |
| 终态过滤 | 重放过滤可能吞掉终态并推进游标，后端结束后界面仍显示“正在思考”；仅放行今后的终态无法修复已吞掉的状态。 |
| 恢复成本 | 打开链路多次完整解码日志，再全量重放到无界缓冲；历史越长，打开越慢。 |
| 展示存储 | App 加载完整聊天记录，并整份重写历史、草稿和待发送内容。 |
| 附件 | 普通已发送附件主要是文件引用；草稿附件以内嵌 Data 保存，模型图片以 Base64 随上下文保存。 |
| 恢复一致性 | 展示事件、模型上下文和任务状态分别落盘，模型上下文主要在一轮结束时保存，中途退出可能恢复到不同位置。 |

现场日志样本有 684,540 条事件、63,317,525 字节，其中 643,566 条思考增量占约 86%。该样本的模型上下文约 233 KB，没有图片块。因此本次日志膨胀主要来自细碎事件，附件内嵌是另一条需要治理的增长路径。现场约 104–105 秒才开始转发历史是端到端观测，不能全算作 JSON 解码时间；尚无充分证据将事故定性为互斥锁死锁。

相关入口：

- [AgentHandler](../../Apelind/Dispatch/AgentHandler.swift)、[AgentWorker](../../Packages/ApelinAgent/Sources/ApelinAgentWorker/AgentWorker.swift)：打开及事件转发。
- [SessionEventLog](../../Packages/ApelinAgent/Sources/ApelinAgent/Persistence/SessionEventLog.swift)、[AgentSession](../../Packages/ApelinAgent/Sources/ApelinAgent/Session/AgentSession.swift)：日志与模型恢复。
- [ChatStore](../../Apelin/Interface/Chats/ChatStore.swift)、[ChatRuntime](../../Apelin/Interface/Chats/ChatRuntime.swift)、[ComposerDraft](../../Apelin/Interface/Chats/Composer/ComposerDraft.swift)：展示历史与附件。
- [TaskRegistry](../../Apelind/Session/TaskRegistry.swift)：宿主任务历史与终态。

原始现场材料只保存在受控诊断位置，不提交聊天正文、附件、凭据或设备标识。进入仓库的复现数据须脱敏或合成，并保留触发问题所需的结构。

## 跨版本一致性规则

1. 每个会话只有一个有效写入者；事件必须匹配当前运行实例，旧实例的迟到事件不能进入新实例。
2. 明确区分会话 ID、运行实例、单轮执行、宿主任务和事件游标。会话的一轮结束不等于承载会话的任务结束。
3. 日志和明确提交的检查点记录持久化事实；展示缓存、分页索引、列表摘要均可重建。不能让多个独立文件各自成为冲突的权威状态。
4. 终态独立于历史过滤处理，不倒退；已经消费过终态的旧记录也能通过状态查询收敛。
5. 超时表示结果未知。重试复用逻辑操作身份；已接收消息必须处于待处理、已处理或中断状态，不能因为去重集合已有 ID 而静默丢弃。
6. 保留任务日志的残缺尾行处理、不可读事件占位和终态恢复规则。缓存或单个聊天损坏不能让全部聊天不可用。
7. 文件引用只接受经过范围和身份校验的文件。附件先保存完整，再提交引用；缺失或损坏不得默认为空内容继续运行。
8. 新增或调整协议时，同步更新操作声明、请求响应类型、宿主及 worker 分发和 AGENTS.md；新旧组件通过能力协商选择路径，不把后端能力做成打包差异。

### 0.2.7 生命周期与旧日志处理

**改动范围**

- 宿主按会话合并正在进行的打开操作，每个调用者仍独立校验项目、权限和请求兼容性；不得复用其他调用者的响应身份或批准。
- worker 在第一次异步等待前进入初始化状态；初始化失败清理占位，使后续请求可以重试。关闭一个等待方不误取消其他等待方共同等待的打开。
- 按当前 worker 实例接收事件和退出回调，隔离旧实例。
- 处理成功、失败、取消和中断，包含空批次的权威终态，以及游标已越过被吞终态的旧聊天。
- 将恢复所需的重复日志扫描合并为一次流式扫描，汇总序号、消息去重、标题和遗留审批等信息。
- 原始日志落盘前有界合并相邻文字和思考增量；消息结束、工具边界、错误和终态前刷新，不跨消息合并，不改写旧日志。
- 增加打开各阶段耗时、扫描字节数、事件数量、队列长度及持久化失败指标。诊断只记录必要元数据，不记录敏感正文。

**验收要求**

- 同会话 20 个并发打开、初始化超过 30 秒后的重试，只产生一个有效初始化与任务；不同项目或不兼容请求不能错误合并。
- 初始化失败可重试；旧 worker 的输出及退出回调不影响替代实例。
- 各类终态和“空批次但任务已结束”均使 UI 收敛；已吞终态的现场复现通过，草稿和历史不丢失。
- 原打开链路不再完整解码同一日志四遍，不同时保留多份完整事件数组。报告旧数据扫描次数和新日志事件量、字节数的前后对比。
- 合并前后最终文本、消息边界、工具顺序和终态一致。明确尚未提交的流式尾部可损失上限，并用强杀验证；已确认接收的用户消息和关键状态不纳入可丢缓冲。
- 写盘失败不能被吞掉后继续宣称保存成功。此版不以彻底消除所有长历史延迟为交付承诺。

**回滚要求**

保持旧格式，可在停止新进程写入后退回 0.2.6。合并后的文字仍是旧版可读事件，无需拆回 token。已纠正的聊天状态仍可读取，但旧版缺陷可能再次出现。验收包括新版写入后由旧版读取的实际演练。

### 0.2.8 历史分页与附件读写

**改动范围**

- 建立稳定会话事件身份和明确的快照／历史边界，分开状态查询、运行恢复与历史分页；发送新消息不等待完整展示历史转发。
- 历史与实时输出按游标衔接。返回同时受条数、字节数约束；慢读者通过背压或断开后按游标重读恢复，不通过无界缓冲，也不静默丢事件。
- App 启动读取聊天摘要、草稿及必要状态；打开聊天先显示最近一页，向前翻阅再读旧内容。
- 展示历史采用追加缓存和可重建索引，草稿、标题和少量新输出不重写全部历史。提供新旧格式读取、逐会话转换和反向导出。
- 草稿及待发送附件外置，发送继续通过文件描述符传递。附件读取离开主线程，缓存按字节数限制；保留仍被草稿、队列或迁移数据引用的文件。
- 宿主已结束任务的事件按需读取，并限制缓存；任务文件格式及构建、安装、环境任务的恢复语义不变。
- 模型上下文继续使用旧格式，不在本版切换模型恢复机制。

**验收要求**

- 百万事件下，读取固定一页的额外内存不随全部历史线性增长；宿主已结束任务增加时，完整事件数组不全部常驻。
- 索引就绪后最近一页显示 P95 目标不超过 2 秒；状态查询和取消确认 P95 目标不超过 1 秒，取消确认不等于工具已停止。目标按下文统一测量协议验收。
- 静态历史分页无缺失、无重复；分页期间新增输出、断连和重启后接续正确；读取历史不启动模型或重执行工具。
- 大附件草稿下持续输入，JSON 写入量不随图片体积增长；选取后强杀、发送途中断连、确认前后重启均保留正确的文字、附件和提交身份。
- 删除可重建缓存后，消息、工具顺序及状态一致。不可重建的本地未发送内容不得作为缓存删除；旧日志尚不能恢复的信息必须先保留再迁移。
- 单个聊天损坏不阻塞聊天列表；磁盘满、附件缺失、慢消费者和快速切换聊天都有明确且可恢复的状态。
- 原构建、安装、环境任务的继续、取消、损坏日志和终态测试全部通过；不重复安装、不重跑已完成任务、不删除既有产物。

**回滚要求**

优先在当前版本关闭新读取路径并重建展示缓存。降级到 0.2.7 前，停止相关写入，用当前版本将新增历史、草稿、队列和外置附件完整导出为旧 `ChatRecord`，校验后再降级。不能恢复迁移前备份来代替导出，否则会丢掉切换后的消息。空间不足或导出失败时保留当前数据，不进行有损降级。

### 0.2.9 模型恢复与图片持久化

**改动范围**

- 使用固定 kwwk revision 的公开事件和状态接口，在完整消息、工具结果、压缩等经验证的安全边界保存检查点；不在每个 delta 重编码完整上下文。
- 检查点关联日志位置、上下文版本、消息接收与处理状态、执行阶段以及恢复所需的 Apelin 提示词状态。覆盖自动和手动压缩，不能仅依据消息数量判断上下文是否变化。
- 检查点先写入独立文件并完成规定的持久化，再发布提交记录；提交前关联日志及附件必须完整。保留上一份有效检查点，孤立文件不视作已提交版本。
- 模型图片独立保存，向 kwwk 提供上下文时还原为原有 `Message` / `ImageContent`。不改工作区路径语义，不重新压缩图片，不丢弃原有供应商字段。
- 恢复区分可继续、中断和工具副作用结果不确定。结果不确定时不自动重执行；本版不承诺指令级或工具执行中点的恢复。
- 完成旧上下文的逐会话转换、核对与反向导出，运行三个版本累计后的完整故障矩阵。

**验收要求**

- 在接收后未执行、工具执行后未落结果、上下文保存后未发布终态、检查点部分写入和提交失败处强杀 App、worker 或宿主，恢复后的消息与状态明确且一致。
- 已接收消息不会因去重集合已有 ID 而消失；未确定完成的副作用不会自动重放。审批不能因恢复而被重新授予。
- 自动／手动压缩、取消、排队消息和工具错误均有检查点契约测试；普通追加不能退化为每个事件全历史重写。
- 保存再恢复的模型消息保留正文、工具调用关系、签名及不透明字段；图片字节一致，构造的模型请求与原格式在相同输入条件下语义一致。
- 持久化上下文不再重复内嵌整份图片 Base64。单独报告 kwwk 活跃上下文和请求编码的峰值内存，不以磁盘缩小冒充内部惰性加载。
- 检查点损坏可回到上一个有效版本，并将无法确定的尾部标记中断；迁移中断、附件缺失和空间不足不覆盖唯一有效数据，不默默省略图片继续运行。
- 固定 kwwk revision 不变，原模型压缩、提示词缓存、工具及供应商回归通过。

**回滚要求**

用当前版本停止会话并整理未完成轮次，选取有效检查点，将模型上下文和图片还原为 0.2.8 可读格式，同时导出对应的消息与终态。校验成功后才能降级；存在旧格式无法无损表达的待处理状态时，应保留当前版本读取和恢复能力，不丢弃状态来强行降级。要退回 0.2.7，继续执行第二版的 App 数据导出。原文件及附件在迁移和回滚验证结束前保留。

## 统一测量与故障验证

验证集包含脱敏现场结构、已吞终态且游标已推进的聊天、十万与百万事件、多长会话、接近现有限制的图片和普通附件、待发送队列、残缺尾行、内部损坏及磁盘满场景。

每次记录设备能力、系统与 bootstrap 类型、构建标识、数据规模、冷暖状态、索引是否存在、样本数、P50/P95、峰值内存、读写字节数和最大队列占用。时延场景每项至少重复 30 次；模型采用可控响应，真实供应商网络另列，不混入本地存储指标。

第二版的 1 秒／2 秒为初始性能门槛，实施前在目标真机和最低支持平台上确认。若不能满足，应说明瓶颈并显式修订门槛，不能在发布验收时直接降低。首次索引构建或迁移单独统计，允许更长耗时，但须有进度、可中断，并且不能冒充模型“正在思考”。模型上下文加载可能仍有成本，也必须单列。

覆盖 roothide、rootless、最低支持平台，以及 iPhone／iPad 布局。vphone 用于回归，真机用于性能与生命周期验证。持续展示历史和运行控制的资源隔离，不能只测空闲状态下单次打开。

## 迁移与版本兼容

| 数据 | 0.2.7 | 0.2.8 | 0.2.9 |
| --- | --- | --- | --- |
| App 展示与草稿 | 旧格式 | 新格式及旧格式读取、导出 | 保留第二版兼容与导出 |
| 模型上下文 | 旧格式 | 旧格式 | 检查点与图片引用，保留旧格式读取、导出 |
| 宿主任务文件 | 旧格式 | 旧格式，读取策略调整 | 保持兼容 |

每次格式切换都在所属版本内按“兼容读写验证 → 副本转换 → 单会话切换 → 扩大范围”推进，不增加计划中的产品版本数。活动会话先停止或取得经验证的独占提交边界；同一阶段只有一个权威写入源，禁止两套存储独立异步写入后再猜哪份正确。

转换前按实际数据计算新旧副本、附件、暂存和回滚导出所需空间；不足时不切换。新数据校验完成后原子发布格式选择，切换中断可以继续或放弃。索引须验证所指日志身份和边界，不能因旧版写过同名文件仍沿用过期偏移。

旧版二进制不会因新文件带有版本号就自动理解新格式。降级必须先在支持新格式的版本中导出，不能把安装旧包作为迁移回滚手段。回滚演练须在切换后继续产生消息和附件，再验证旧版读取结果；只验证迁移前备份不算通过。

## 每版发布门槛

每版可拆多个 PR，但下列门槛全部通过后才发布，再开始下一版的数据切换：

1. 对应正确性、故障注入、性能与回滚要求全部有结果；新增测试针对失败机制，不只镜像实现。
2. 按 AGENTS.md 执行 `make harness`、`make check` 及受影响的设备回归。协议、持久化或 worker 变更使用完整匹配包验证，不只替换 App。
3. 本版在受控设备完成冷启动、App 强杀、worker／宿主重启、长会话继续发送和实际降级演练后，再扩大使用范围。
4. 核对 kwwk pin 未变；审查迁移产物、日志和提交中没有聊天正文、凭据、设备标识或本机路径泄漏。
5. 保存本版与回滚版安装包和对应 dSYM。CI 构建通过后再打标签，发布 CI 已验证的同一份产物；发布说明写入 `Documents/Releases/`。

已确认消息丢失、重复副作用、终态倒退、权限变化或无法无损导出，任一出现即停止扩大上线范围，保留现场并修复。前一版验收未完成时不把其未解决问题混入下一版的新格式切换。
