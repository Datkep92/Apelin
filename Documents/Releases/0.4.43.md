# 0.4.43

Combines the retry-provenance and startup-optimization work into one release: chat history and events load on demand, retry remembers its message and never repeats a failed key, and the ChatRuntime log calls compile.

## What changed

- Chat events are stored in a separate file per conversation and loaded only when the conversation is opened or is actively working, instead of loading every conversation's full history at launch.
- Startup reconciliation runs in the background and loads events only for working or live sessions.
- Removed unused event data from the in-memory record after persisting, reducing memory pressure.
- Fixed `os_log` calls in ChatRuntime that used an invalid `subsystem:` argument label, which prevented compilation.
- Automatic retry now remembers which message it is answering, so a newer message sent in the meantime is not retried instead.
- A model failure is recorded on its own, alongside the error, so the app can tell retryable failures apart.
- A key that has already failed in a retry chain is never tried again, even after its cooldown or when Retry is pressed manually.
- When every candidate has been tried, the retry stops and the error stays on screen.
