# Release notes

One file per version, `<version>.md`, written before the tag; the Release
workflow publishes it as the release body. The shape: one headline sentence
saying what the release does, one bullet per user-visible change in the
user's words with the symptom first, and a closing line naming the package
to choose (`iphoneos-arm64e` for RootHide, `iphoneos-arm64` for rootless)
and `SHA256SUMS`. No commit shas, no internal names, no generated compare
link.
