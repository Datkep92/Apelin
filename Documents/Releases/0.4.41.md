# 0.4.41

Makes the Gateway switch behave correctly: turning it on while the gateway is already serving no longer restarts it, a gateway that is running but not answering is shown as not responding and can be turned off, and the Settings row now says what the switch really controls — the local gateway on port 15199.

## What changed

- Turning the switch on when the gateway is already running does nothing instead of starting it a second time.
- A gateway process that exists but no longer answers the port now keeps the switch on, with "Gateway is not responding" beside it, so it can be turned off; turning it on in that state stops the stuck process first and starts a clean one.
- Turning the switch off only acts when something is actually running.
- The Settings row no longer claims the switch connects to GitHub, Firebase, Cloudflare, Google Script and Telegram; it says it controls the local gateway on port 15199.
